# 工作台模块 PRD

**版本**：V1.4（按现网演示口径修订）  
**模块名称**：工作台（个人任务中心）  
**最后更新**：2026-08-12  
**适用项目**：`project_qingpu_pc`  
**业务基线**：角色×模块×状态（动作）主表（已拍板 D1/D3/C1；V1.4 补充节点/资金进度/催办展示规则）  
**配套清单**：`docs/ux/工作台/待办事项清单.md`

---

## 需求目标

将各业务模块产生的、需当前登录人处置的事项，统一汇聚到「工作台」，按角色只展示其应办任务，通过统一四态与动作按钮完成处置/审核/确认/查阅，并支持一般性催办提示，减少跨模块查找成本，提升个人任务闭环效率。

---

## 需求说明

1. 左侧菜单最后保留一级模块「工作台」，路由 `/workbench`。
2. 按登录角色聚合个人待办，覆盖 11 类来源（见功能 1 主表）。
3. 工作台展示状态固定为：`待处置 / 待审核 / 待确认 / 待查阅`；主按钮与动作对应（去填报/去修改/去初审/去终审/去处置/去审核/去确认/去查阅/查看处置等）。
4. 卡片须同时标明 **业务状态** 与 **应做动作**（例：业务状态「待确认」→ 动作「审核」；「待完结」→ 动作「确认」）。
5. 用户在工作台弹窗内完成处理（本期不强制跳转业务页）。
6. 提供统计卡、筛选、逾期标识、菜单角标；催办提示计入「待查阅」及角标。
7. 谋划库/退库/增补库：专员侧仅「退回」进台；首次主动申报不进工作台。
8. 分管侧状态文案统一为「分管领导待初审」（不以「分管领导待审核」混用）。
9. **项目节点审核**：专员侧「待填报」不进工作台，仅「审核退回」进台；卡片/详情展示 **处置节点**。
10. **标题口径**：
    - 退回类：冒号后展示 **退回原因**；
    - 待初审 / 待终审：标题不加后缀；
    - 领导交办 / 难题协调（非退回）：冒号后展示 **事项内容**。
11. **资金 / 形象进度**：来源名与状态对齐业务主表（见 §2.4）；资金可从【项目详情】进入填报。
12. **催办弹窗**：应做动作为「查看处置」；「事项 + 关联项目」成组展示，多条分开放。
13. 演示环境支持角色切换含 **系统管理员**（查看全部未完成待办；同事项同状态去重仅留一条）。
14. 本期不做：批量处理、导出、催办策略引擎全量对接、外部消息通道配置页。

## 一、原型

### 1.1 页面布局原型（文本）

1. **顶部**：标题「个人任务中心」（无副标题说明文案）；右侧演示用角色切换（项目专员 / 分管领导 / 片区专员 / 市领导 / 部门一把手 / **系统管理员**）。
2. **统计区**（可点击联动状态筛选）：
   - 待办总数
   - 待处置
   - 待审核
   - 待确认
   - 待查阅（含催办提示）
3. **筛选区**：
   - 关键词（标题 / 项目名称 / 项目编码 / 摘要）
   - 来源业务（11 类 + 全部）
   - 工作台状态
   - 接收时间范围
   - 是否逾期
4. **列表区**（任务卡片）：
   - 标签：逾期（仅当该卡展示截止时间且已逾期）、业务状态、动作；节点类另标「节点：xxx」
   - 标题、项目名、项目编码、摘要
   - 催办类额外展示：催办条数、催办人、催办时间
   - 接收时间；**截止时间**仅领导交办 / 难题协调 / 上级资金填报 / 形象进度填报展示
   - 右侧主操作按钮（随动作变化）
5. **详情/处理弹窗**：
   - 只读：来源、业务状态、应做动作、工作台状态、关联项目、（节点）处置节点、时间、摘要、催办信息（如有）
   - 催办类：按「催办事项 n」分组展示 **关联事项 + 关联项目**（成组；多条分开放）
   - 按动作类型展示：审核结论、确认说明、催办「知道了」、或处置确认

### 1.2 路由与入口

| 项 | 说明 |
|---|---|
| 菜单 | 一级菜单「工作台」（位于菜单最后） |
| 路由 | `/workbench` |
| 角标 | 当前登录人未完成待办数（含催办提示）；管理员为去重后的全部未完成数 |

### 1.3 信息架构（简图）

```text
工作台菜单
 └── 个人任务中心
      ├── 统计卡（四态）
      ├── 筛选区
      ├── 待办卡片列表
      │    ├── 业务处置类 → 处置弹窗
      │    └── 催办提示类 → 催办说明弹窗（事项×项目成组）
      └── （演示）角色切换（含系统管理员·全部）
```

## 三、需求内容

### 1、功能1：待办聚合总览

#### （1）功能点

1. 按当前登录人聚合未完成待办，口径对齐 §2.4 主表；管理员为全部未完成（事项×状态去重）。
2. 展示待办总数及四态数量；点击统计卡联动状态筛选。
3. 菜单角标 = 未完成待办总数；催办提示计入「待查阅」与角标（C1 已确认）。
4. 排序建议：逾期优先 → 截止时间升序 → 接收时间倒序。

#### （2）页面结构

1. 页面标题区（仅标题，无解释文案）。
2. 统计卡片区：总数 + 待处置 / 待审核 / 待确认 / 待查阅。
3. 其下为筛选区与列表区（见功能 2）。

#### （3）字段说明

| 展示项 | 说明 |
|---|---|
| 待办总数 | `status ≠ done` 条数（去重后） |
| 待处置 | `pending_dispose` |
| 待审核 | `pending_review` |
| 待确认 | `pending_confirm` |
| 待查阅 | `pending_read`（含催办提示） |

#### （4）交互规则

1. 点击某一状态卡：状态筛选项设为该状态并刷新列表；再次点「待办总数」恢复全部。
2. 处理成功或切换演示角色后：刷新列表、统计与角标。
3. 无待办时统计均为 0，列表空态提示「暂无待办事项」。

#### （5）权限细化

- 普通角色仅统计本人数据；系统管理员统计全部（去重后）。

### 2、功能2：筛选与待办列表

#### （1）功能点

1. 支持关键词、来源业务、工作台状态、接收时间、逾期筛选。
2. 卡片列表展示来源、业务状态、动作、项目信息、摘要、时间、主按钮。
3. 业务状态与动作同时展示，避免「待确认」语义混淆（D3 已确认）。
4. 项目节点审核展示处置节点；标题遵循 §需求说明 第 10 条口径。

#### （2）页面结构

1. 筛选表单（一行或多行自适应）。
2. 卡片列表 + 底部分页（客户端分页可接受 MVP）。

#### （3）字段说明

**列表/卡片字段**

| 字段 | 必填 | 说明 |

| 来源业务 | 是 | 11 类枚举展示名 |
| 业务状态 | 是 | 业务模块状态原文 |

| 工作台状态 | 是 | 四态之一 |
| 标题 | 是 | 见标题口径（退回原因 / 事项内容 / 待初审终审无后缀） |
| 项目名称 / 项目编码 | 否 | 关联项目 |
| 处置节点 | 条件 | 仅项目节点审核 |
| 摘要 | 否 | 说明文案 |
| 接收时间 | 是 | 进入工作台时间 |
| 截止时间 | 条件 | 仅领导交办、难题协调、上级资金、形象进度 |
| 是否逾期 | 算 | 仅当展示截止时间且早于当前 |

#### （5）权限细化

### 3、功能3：任务处置弹窗

#### （1）功能点

1. 在弹窗内完成填报/修改/初审/终审/处置/审核/确认/查阅等（MVP 可简化表单，以确认+必要意见为主）。
2. 审核类支持通过/退回，意见必填。
3. 确认类需确认说明必填。
4. 提交成功后关闭本待办；业务侧按各模块流程生成下一岗待办（实现阶段对接业务或 mock 流转）。

#### （2）页面结构

1. 弹窗标题：来源业务 · 任务标题。
2. 只读描述区（关联项目；节点类含处置节点）。
3. 操作区：按 `actionCode` / 工作台状态切换表单。
4. 底部：取消 / 确定。

#### （3）字段说明

| 字段 | 场景 | 必填 | 说明 |
|---|---|---|---|
| 审核结论 | 待审核类 | 是 | 通过 / 退回 |
| 审核意见 | 待审核类 | 是 | 文本 |
| 确认说明 | 待确认类 | 是 | 文本 |
| 处置确认 | 待处置类 | — | MVP 可仅确认完成 |
| 处置节点 | 节点审核 | — | 只读，标明当前处理节点 |
| expectedUpdatedAt | 提交 | 是 | 乐观锁，防并发 |

#### （4）交互规则

1. 提交前校验必填；失败 toast 提示。
2. 并发冲突：提示「任务状态已变更，请刷新」。
3. 查阅：确认已阅后关闭待办（不可退回重开，沿用既有查阅口径）。
4. 成功后刷新列表、统计、角标。

#### （5）权限细化

- 仅当前处理人可提交；前端隐藏 + 后端校验（生产）。

### 4、功能4：催办提示（协调催办 / 交办催办）

#### （1）功能点

1. 以一般性催办提示卡片展示，不替代业务处置待办。
2. 文案示意：`您有 x 条协调/交办催办提示，请尽快关注办理。`
3. 支持查看催办摘要，并「知道了」标记提示已阅。
4. 计入待查阅统计与菜单角标。
5. 弹窗内 **应做动作 = 查看处置**；关联内容按「事项 + 项目」成组，多条分开放。

#### （2）页面结构

1. 列表中的催办卡片（来源=协调催办/交办催办）。
2. 弹窗：基础只读信息 + 催办信息 + **催办事项分组列表**（每组：关联事项、关联项目）。

#### （3）字段说明

| 字段 | 说明 |
|---|---|
| urgeCount | 催办条数 |
| urgerName | 催办人（或「系统」） |
| urgedAt | 催办时间 |
| relatedItems[] | 成组列表：`matter`（关联事项）+ `projectName`/`projectCode`（关联项目） |
| 应做动作 | 固定文案「查看处置」 |

#### （4）交互规则

1. 按钮「查看处置」打开弹窗；确定=标记已阅，不关闭业务侧处置待办。
2. 多条催办：弹窗内展示「催办事项 1」「催办事项 2」…，每组内事项与项目为一体，组与组分开。
3. 本期不实现催办限频、工作日算法、多通道发送（见 `docs/file/消息发送配置.xlsx`，二期）。
4. 角色可见性默认：  
   - 协调催办：专员、分管、片区、部门一把手（与本人相关时）  
   - 交办催办：专员、片区、市领导（与本人相关时）

#### （5）权限细化

- 仅本人相关催办提示；不可代阅他人催办（管理员演示除外）。

### 5、功能5：演示角色切换与角标刷新

#### （1）功能点

1. 页面提供角色切换，便于验收不同角色待办（非生产登录）。
2. 切换后重新拉取待办并刷新菜单角标。
3. **系统管理员**视角：全部未完成待办，且按「来源事项 × 业务状态」去重。

#### （2）页面结构

- 标题区右侧：当前用户名（角色）+ 角色下拉。

#### （3）字段说明

| 角色选项 | 展示名 |
|---|---|
| projectSpecialist | 项目专员 |
| supervisor | 分管领导 |
| districtSpecialist | 片区专员 |
| cityLeader | 市领导 |
| deptHead | 部门一把手 |
| admin | 系统管理员 |

#### （4）交互规则

1. 切换角色 → 重置筛选 → 加载待办 → 广播 `workbench:updated` 刷新角标。
2. toast 提示已切换视角。

#### （5）权限细化

- 仅演示环境使用；生产以真实登录角色为准，隐藏切换器。

## 四、异常与边界（补充）

| 场景 | 处理 |
|---|---|
| 空列表 | 空状态「暂无待办事项」 |
| 筛选无结果 | 可提示重置筛选 |
| 加载/提交中 | Spin / 按钮 loading，防重复提交 |
| 长标题/摘要 | 折行或省略 |
| 上级资金与形象进度 | 同项目可并存多条（周进度与月进度资金分条） |
| 催办与业务待办同时存在 | 两条均展示，不合并掉处置入口 |
| 管理员全量视图 | 同事项同状态去重，避免重复卡片 |
