# 工作台模块 PRD（模板版）

**版本**：V1.0（MVP）  
**模块名称**：工作台（个人任务中心）  
**最后更新**：2026-07-29  
**适用项目**：`project_qingpu_pc`

---

## 需求目标

将各业务模块分散的待办事项集中到统一入口，提供按状态快速处置、审核、确认、查阅能力，减少跨模块跳转成本，提升个人任务闭环效率。

---

## 需求说明

1. 在左侧菜单最后新增一级模块`工作台`。
2. 聚合全部业务模块待办（MVP 阶段使用 mock 数据）。
3. 统一待办状态：`待处置 / 待审核 / 待确认 / 待查阅`。
4. 用户在工作台内弹窗完成任务处理，不跳转来源模块页面。
5. 提供统计卡、筛选器、逾期提醒、菜单角标。
6. 当前阶段仅支持个人视角，不支持批量、不支持导出、不接入外部消息。

---

## 一、原型

### 1.1 页面布局原型（文本）

1. 顶部：标题“个人任务中心”+说明文案。
2. 统计区：
   - 待办总数
   - 待处置
   - 待审核
   - 待确认
   - 待查阅
3. 筛选区：
   - 关键词（项目名/项目编码/任务标题）
   - 来源模块
   - 状态
   - 接收时间范围
   - 是否逾期
4. 列表区（任务卡片）：
   - 标签（来源模块、状态）
   - 标题、项目名、项目编码、摘要
   - 接收时间、截止时间
   - 右侧主操作按钮（随状态变化）
5. 详情/处理弹窗：
   - 在当前页面弹窗内进行处置/审核/确认/查阅

### 1.2 路由与入口

- 菜单：一级菜单`工作台`（位于最后）
- 建议路由：`/workbench`

## 三、需求内容

### 1、功能1：工作台待办聚合总览

#### （1）功能点

1. 聚合全部模块个人待办，统一展示。
2. 展示待办总数及四状态数量。
3. 点击状态卡片可快速过滤列表。
4. 菜单显示待办总数角标，并随处理动作刷新。

#### （2）页面结构

1. 页面标题区：模块名称与描述。
2. 统计卡片区：总数 + 四状态卡。
3. 筛选区：关键词、来源、状态、时间、逾期。
4. 列表区：任务卡片（支持分页）。

#### （3）字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | string | 是 | 待办唯一ID |
| title | string | 是 | 待办标题 |
| projectName | string | 否 | 项目名称 |
| projectCode | string | 否 | 项目编码 |
| sourceModule | enum | 是 | 来源模块 |
| status | enum | 是 | 待处置/待审核/待确认/待查阅 |
| tags | string[] | 否 | 标签，默认含来源模块 |
| receivedAt | datetime | 是 | 接收时间 |
| dueAt | datetime | 否 | 截止时间 |
| isOverdue | boolean | 是 | 是否逾期 |
| summary | string | 否 | 摘要说明 |
| actionLabel | string | 是 | 去处置/去审核/去确认/去查阅 |

#### （4）交互规则

1. 默认筛选：来源=全部，状态=全部，时间=不限，逾期=全部。
2. 支持组合筛选；筛选变化后回到第一页。
3. 列表为空时展示空态“暂无待办事项”。
4. 无截止时间任务不参与逾期计算，截止时间显示`—`。

#### （5）权限细化

1. 仅本人可见本人待办。
2. 不提供跨人查看入口。

---

### 2、功能2：按状态快速处理（弹窗内）

#### （1）功能点

1. 每条任务仅一个主操作按钮。
2. 按状态打开对应处理弹窗。
3. 提交后刷新列表、统计卡、菜单角标。

#### （2）页面结构

1. 列表卡片右侧操作区。
2. 处理弹窗区（动态内容按来源模块渲染）。

#### （3）字段说明

| 状态 | 按钮文案 | 处理结果 |
|---|---|---|
| 待处置 | 去处置 | 完成后置为 done 或流转待确认 |
| 待审核 | 去审核 | 审核通过/退回，更新任务状态 |
| 待确认 | 去确认 | 确认后置为 done |
| 待查阅 | 去查阅 | 标记已阅后置为 done |

#### （4）交互规则

1. 操作在工作台内弹窗完成，不跳转来源模块。
2. 提交前执行必填校验，失败时阻止提交并提示。
3. 并发冲突提示“任务状态已变更，请刷新”。

#### （5）权限细化

1. 仅任务所属人可提交处理动作。
2. 非所属人（后续扩展场景）仅可查看不可提交。

---

### 3、功能3：逾期提醒与任务可视化

#### （1）功能点

1. 自动识别逾期任务并高亮。
2. 支持“仅逾期/仅未逾期”筛选。
3. 在统计与列表中体现紧急程度。

#### （2）页面结构

1. 筛选区逾期开关。
2. 列表卡片截止时间样式区。

#### （3）字段说明

| 字段 | 规则 |
|---|---|
| isOverdue | `dueAt < now && status != done` 为 true |
| dueAt | 为空时不参与逾期判断 |

#### （4）交互规则

1. 逾期项截止时间使用警示色。
2. 可附加“逾期”标签（样式层实现）。

#### （5）权限细化

逾期规则与权限无关，按任务数据统一计算。

## 四、状态定义与流转

### 4.1 状态定义

| 状态 | 定义 |
|---|---|
| 待处置 | 需要用户执行业务动作，但不一定审批 |
| 待审核 | 需要用户执行审批决策 |
| 待确认 | 需要用户确认或回执 |
| 待查阅 | 仅查看阅读 |
| done | 已完成（移出待办） |

### 4.2 状态机

| 当前状态 | 动作 | 前置条件 | 下一状态 |
|---|---|---|---|
| 待处置 | 提交处置 | 校验通过 | done / 待确认 |
| 待审核 | 审核通过/退回 | 审核信息完整 | done / 待处置 |
| 待确认 | 提交确认 | 校验通过 | done |
| 待查阅 | 标记已阅 | 无 | done |
| 任意待办态 | 超过截止时间 | dueAt 非空且当前时间超出 | 保持原状态 + 逾期标记 |

## 六、验收标准

1. 左侧菜单最后新增`工作台`并可访问。
2. 展示总待办与四状态统计卡。
3. 支持关键词、来源、状态、时间、逾期筛选组合。
4. 列表字段完整：标题、项目名、项目编码、来源、状态、接收时间、截止时间、摘要、标签。
5. 按钮文案固定且行为正确（去处置/去审核/去确认/去查阅）。
6. 处理动作在弹窗内完成，提交后刷新统计、列表、角标。
7. 逾期项有明显视觉提示。
8. 不支持批量处理、不支持导出、不接外部消息。
9. 仅展示个人待办。

---

## 七、非功能与边界

1. 首屏加载（mock）目标 <= 2s。
2. 常规交互响应目标 <= 500ms（mock 环境）。
3. 空数据、并发冲突、时间异常需有明确提示与兜底策略。
